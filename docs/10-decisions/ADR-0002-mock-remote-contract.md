# ADR-0002：Mock 与真实后端共享 HTTP 契约

- 状态：Accepted

## 背景

前端需要在 Java Server 未启动时独立开发，同时必须避免假数据接口与真实接口形成两套实现。

## 决策

使用 OpenAPI 3.1 作为唯一 HTTP 契约，生成 TypeScript 类型。Mock 模式使用 MSW 拦截相同路径，真实后端模式由同一客户端发出真实请求。模式由构建配置显式选择，组件不感知模式。

## 选择原因

- 页面与功能代码不出现数据源分支。
- 浏览器和服务端渲染都能使用相同 Mock 行为。
- 能模拟延迟、错误、权限和异步状态。
- 契约可供 Java Controller、前端客户端和文档共同使用。

## 后果

- 每个端点都必须维护 Mock 处理器和命名场景。
- 运行时 Schema 校验会增加开发环境成本，但能尽早发现漂移。
- 正式构建必须阻止 Mock 资产和配置。

## 未选方案

- 组件内静态数组：无法覆盖写操作和错误状态。
- 独立假 API 形状：极易与真实后端不一致。
- 请求失败自动使用假数据：会隐藏真实故障。
