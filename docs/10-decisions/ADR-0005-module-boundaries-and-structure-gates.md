# ADR-0005：模块边界与结构门禁

- 状态：Accepted

## 背景

系统功能已经覆盖公开站点、用户工作区、管理后台、Java 业务模块与存证网关。随着纵向切片增多，若继续把管理用例、Mock 状态和跨模块读取集中在少数大文件中，代码仍可编译，但审查成本、循环依赖和修改冲突会持续上升。

## 决策

1. Web 保持薄路由，功能组件默认不超过 450 行。管理工作台按业务分区拆分，资源编辑器拆分为加载边界、状态 Hook 与展示组件。
2. Mock 与真实后端继续共享 OpenAPI 和 HTTP 客户端。Mock handler 按端点域拆分，state 按种子、存储、辅助函数与业务切片拆分。
3. Java 管理端不保留万能 Controller 或 Service，按总览、用户、内容、分类、存证和可观测性组织用例；公共返回模型由专用 Mapper 负责。
4. API 可见枚举位于模块 `domain` 包，持久化 Entity 引用领域枚举；DTO 不依赖 `entity` 或 `repository`。
5. 单向模块协作仍通过公开 Service。仅在双向协作可能形成实现环时，引入 `platform/port` 的窄接口和 `platform/contract` 的稳定快照。
6. `shared` 保持纯底层技术内核。认证主体、安全过滤器装配和运行环境保护属于组合根能力，位于 `platform/security`。
7. 根目录提供自动结构检查，和编译、类型检查、测试、生产构建一起执行。

## 结构预算

- Next.js 路由页：100 行。
- Web 功能组件、管理分区、Mock handler 与 Mock state：450 行。
- Java Controller：300 行。
- Java Service：500 行。

预算用于触发职责审查，不鼓励为了行数机械拆文件。内容语料、生成契约与纯数据清单不按组件预算处理。

## 后果

- 业务用例可以独立定位、审查和修改，管理端与 Mock 层的冲突面显著缩小。
- 知识、存证、用户、社交和认证不再互相注入具体实现，依赖方向可以由自动检查验证。
- 新增功能需要同步选择所属分区、端口或领域模型，不能回到通用大文件。
- 文件数量增加，但每个文件的责任、依赖和测试边界更明确。
