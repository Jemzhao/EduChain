# ADR-0001：Java 后端采用模块化 MVC 单体

- 状态：Accepted

## 背景

系统包含账户、资源、检索、互动、通知、文件、存证和管理等多个能力。毕业设计需要结构清楚、易解释、可独立运行，同时不应承担微服务的部署和一致性成本。

## 决策

采用单一 Spring Boot 应用，按业务模块组织；每个模块内部使用 Controller、Service、Repository、Entity、DTO 和 Mapper。模块间通过公开 Service 门面协作，不直接访问对方 Repository。

## 选择原因

- 完全符合标准 Spring MVC 心智模型。
- 业务边界比全局大层目录清楚。
- 一个数据库事务可以覆盖核心一致性操作。
- 单人项目能够部署、调试和演示。
- 未来确有需要时，模块边界为独立部署提供基础，但当前不预设拆分。

## 后果

- 必须通过架构规则阻止跨模块深层引用。
- `shared` 目录需要严格控制，不能成为杂物箱。
- 管理模块只编排，不拥有其他模块的数据。
- 所有外部副作用使用可靠任务连接，不在长事务中执行。

## 未选方案

- 全局 Controller/Service/Repository 大目录：模块边界弱。
- 微服务：工作量和运行复杂度与项目规模不匹配。
- 完整 DDD/六边形架构：术语和抽象成本超过首版收益。
