# ADR-0003：Intlayer 作为唯一内容与国际化方案

- 状态：Accepted

## 背景

项目需要中文和英文，并要求全局内容统一管理、避免组件内重复文案。先前方案使用 Intlayer，当前版本已支持 Next.js 16、类型安全内容和按组件加载。

## 决策

使用 Intlayer 9.4.1 作为唯一国际化方案。内容按全局、模式、功能和页面四层归属；所有用户可见文案进入类型安全字典；公开页面使用语言前缀路由。

## 选择原因

- 符合项目指定的国际化方案偏好。
- 类型安全并适合组件化内容。
- 支持静态渲染、树摇和 Next.js App Router。
- 可在不依赖在线 CMS 的情况下完成构建。

## 后果

- 禁止同时引入 next-intl、i18next 或其他主国际化框架。
- 需要内容键检查、语言完整性检查和硬编码文案检查。
- 内容归属需要评审，防止全局字典过度膨胀。

## 未选方案

- 手写 JSON 字典：类型和组件归属弱。
- 多框架并存：运行时和维护成本增加。
- 后端直接返回最终展示文案：难以统一体验和语言切换。
