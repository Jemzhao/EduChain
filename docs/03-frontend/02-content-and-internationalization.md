# 全局内容与国际化治理

- 状态：Accepted

## 1. 目标

- 使用 Intlayer 作为唯一国际化与用户内容方案。
- 支持简体中文 `zh-CN` 与英文 `en`，简体中文为默认语言。
- 组件获得类型安全内容，构建时发现缺失键和错误引用。
- 公开页面语言体现在 URL 中，保证可分享、可索引和可缓存。
- 通过内容归属规则消除重复文案和巨大集中式字典两种极端。

## 2. Intlayer 基线

- 包版本基线：`intlayer` 与 `next-intlayer` 9.4.1，同步锁定。
- 使用 Next.js 16 App Router 官方集成方式。
- 路由代理行为使用 9.x 配置模型，明确 `routing` 规则。
- 构建环境默认使用本地类型安全内容文件，不依赖在线 CMS 才能完成构建。
- 可视化编辑器只作为受控开发能力，不在生产页面暴露。

## 3. 内容分层

### 3.1 全局内容

只包含跨功能稳定复用的内容：

- 品牌名称、产品描述和法律名称。
- 全局导航、账户菜单和页脚。
- 通用动作：保存、取消、确认、关闭、重试、复制、删除。
- 通用状态：草稿、处理中、成功、失败、已下架。
- 通用验证语义和错误恢复操作。
- 日期、数字、单位和文件大小标签。
- 通用可访问性标签。

### 3.2 模式内容

空状态、错误页、分页、表格和上传队列等可复用模式拥有独立字典。

### 3.3 功能内容

登录、创作、搜索、互动、存证和管理等功能的独有文案放在各自功能目录中。

### 3.4 页面内容

只在单一页面出现的标题、说明、SEO 文案跟随页面。重复出现两次以上且语义相同的内容提升到功能或全局层。

## 4. 强制规则

- `.tsx` 中不得直接写用户可见字符串，品牌法定标识和技术调试文本除外。
- 不使用句子拼接生成不同语言内容。
- 内容键表达语义，不表达当前中文文本。
- 不用同一个键承载不同上下文中的同形文字。
- 按钮标签、无障碍标签和通知内容分别定义，不假设视觉文本适合作为朗读文本。
- 后端不返回直接展示的自然语言业务错误；返回稳定错误代码和参数。

## 5. 命名规范

内容键建议采用：`scope.subject.intent.variant`。

示例语义：

- `global.action.save.default`
- `resource.publish.status.processing`
- `evidence.verify.result.matched.title`
- `admin.user.action.suspend.confirmation`

键名不包含页面坐标、颜色或临时实现名称。

## 6. 路由与语言选择

- 所有公开页面使用 `/{locale}/...`。
- 语言选择顺序：显式 URL → 已保存偏好 →请求语言 → 默认语言。
- 切换语言时保留同一资源和可兼容查询参数。
- 不支持的语言返回规范重定向或 404，不静默显示错误语言。
- 生成 `hreflang`、规范链接和语言化站点地图。

## 7. 格式化

- 日期时间使用 Intl API 和显式时区语义。
- 数据库存 UTC；界面按用户或系统时区显示。
- 数字、百分比、文件大小和相对时间使用统一格式化器。
- 哈希、交易标识和版本号不做语言转换。
- 中文标点和英文标点由各自完整内容控制。

## 8. 内容质量门禁

- 两种语言键集合一致。
- 不存在空值、占位文本或机器翻译未审标记。
- 重要按钮使用动词，错误消息同时说明问题和下一步。
- 管理动作说明影响范围和可恢复性。
- 存证文案不承诺超出系统能力的法律效力。
- 内容长度以英文较长文本和中文紧凑文本分别检查。

## 9. 内容评审责任

- 产品语义：产品负责人。
- 技术术语：架构负责人。
- 中文质量：中文内容责任人。
- 英文质量：英文内容责任人。
- 无障碍标签：前端与可访问性评审共同负责。
