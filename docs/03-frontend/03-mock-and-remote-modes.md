# Mock 与真实后端双模式

- 状态：Accepted

## 1. 目标

前端在没有 Java Server 时可以完整开发和演示；连接真实后端时不修改页面和功能代码。两种模式唯一允许的差异是数据来源与受控网络特性，不是功能实现。

## 2. 模式定义

| 模式   | 配置值   | 数据来源               | 适用场景                    |
| ------ | -------- | ---------------------- | --------------------------- |
| Mock   | `mock`   | MSW 浏览器/Node 处理器 | UI 开发、交互评审、离线演示 |
| Remote | `remote` | Java Server HTTP API   | 联调、集成环境、正式运行    |

禁止提供 `auto` 模式，避免请求失败后静默回退到假数据。正式构建如果检测到 Mock 模式必须失败。

## 3. 核心结构

```text
UI / Feature
    -> Query or Command
        -> Shared API Client
            -> HTTP request defined by OpenAPI
                -> MSW handler in mock mode
                -> Java Server in remote mode
```

组件不知道当前模式，业务 Hook 也不通过条件分支返回假数据。

## 4. 契约来源

- OpenAPI 3.1 是 HTTP 路径、方法、请求、响应、分页和错误的权威来源。
- 生成 TypeScript 类型和客户端薄层，禁止手写重复接口类型。
- MSW 处理器使用生成类型或共享运行时 Schema。
- Mock 响应在开发时进行运行时校验，错误立即暴露。

## 5. Mock 目录职责

- `handlers`：按业务模块实现 HTTP 处理器。
- `fixtures`：少量稳定的基准对象。
- `factories`：根据参数生成符合约束的数据。
- `scenarios`：组合可复现的页面状态。
- `browser`：浏览器工作器启动和生命周期。
- `node`：服务端渲染、组件预览和后续自动化环境支持。

## 6. 必备场景

每个关键流程至少具备：

- 正常数据。
- 空数据。
- 未登录或会话过期。
- 权限不足。
- 字段校验失败。
- 对象不存在或已下架。
- 网络延迟。
- 可重试服务错误。
- 不可重试业务错误。
- 并发版本冲突。
- 分页首尾边界。

证明流程还必须具备：等待提交、处理中、已确认、结果未知、可重试失败、终止、匹配、不匹配和模拟来源标识。

## 7. 数据一致性

- 工厂生成的数据必须满足数据库唯一性、枚举和长度约束。
- 列表对象和详情对象共享稳定标识与状态。
- 用户权限、资源所有者和页面能力必须相互一致。
- 时间由场景时钟控制，避免每次刷新结果不可复现。
- 分页总数、筛选结果和聚合统计必须可以解释。

## 8. 状态保持

Mock 默认在内存中维护单次会话状态，使创建、编辑、点赞和收藏能形成闭环。需要复位时使用显式开发入口恢复到命名场景。不得把测试数据写入真实浏览器长期存储后影响其他场景。

## 9. 网络模拟

- 默认延迟保持接近本地真实后端，不制造持续等待。
- 特定场景可以配置固定慢响应或超时。
- 随机失败默认关闭，确保问题可复现。
- 错误通过标准错误响应返回，不直接抛出任意 JavaScript 异常。

## 10. 防漂移机制

- OpenAPI 生成产物变化需要评审。
- Mock 处理器覆盖所有前端实际调用端点。
- 示例响应和场景数据通过同一 Schema 校验。
- Remote 环境发现未声明字段时记录契约问题，不在 UI 中临时兼容多个形状。
- 每个功能完成标准同时要求 Mock 场景和真实接口联调记录。

## 11. 环境保护

- 模式在构建阶段确定并显示在开发工具中。
- Mock 模式页面显示低干扰但明确的开发标识。
- 生产环境配置不包含 Mock 工作器资产。
- 任何真实管理或证明演示都必须明确展示当前后端和证明来源。
