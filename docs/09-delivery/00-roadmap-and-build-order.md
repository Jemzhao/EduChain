# 实施路线与构建顺序

- 状态：Accepted

当前结果：阶段 0 至阶段 8 已按纵向切片落实到三个应用、共享契约、数据结构版本脚本、容器编排和交付文档。验证方式受项目约束限制为构建、静态检查和人工页面复核。

## 1. 总原则

- 先冻结契约和视觉基础，再创建工程。
- 先形成最小纵向闭环，再扩展模块数量。
- 每个功能同时交付页面、接口、权限、数据、错误、Mock 场景和观测点。
- 真实长安链可后接，但存证接口、状态机和模拟器必须从第一条存证闭环开始一致。

## 2. 阶段 0：开发前冻结

输出：

- 产品范围、角色权限和页面结构。
- 技术版本、根目录和三个应用目录。
- 设计令牌、组件清单和关键页面线框。
- OpenAPI 端点目录和错误码。
- 数据概念模型与状态机。
- Mock/真实后端双模式规则。
- 质量门禁、风险清单和验收标准。

出口：所有阻断型问题有结论，文档状态进入 Accepted。

## 3. 阶段 1：工程基础

- 建立工作区和三个应用骨架。
- 配置格式、静态检查、环境校验和依赖锁定。
- 建立设计令牌、Intlayer、API 客户端、MSW 和统一错误边界。
- 建立 Java MVC 基础、Problem Details、身份骨架和数据库版本管理。
- 建立 Gateway 配置、健康检查和适配器接口。

阶段结果不追求大量页面，只验证边界可运行。

## 4. 阶段 2：身份与资料纵向闭环

- 注册、登录、刷新、退出、本人资料和公开主页。
- Mock 场景、Java API、MySQL、权限和错误全部贯通。
- 导航、表单、通知反馈和基础可访问性成型。

## 5. 阶段 3：资源创作与发布闭环

- 草稿、编辑、自动保存、上传、预览和发布。
- 资源公开详情、版本和作者展示。
- 文件检查、发布事务、并发控制和可靠任务。
- 初始设计系统在真实复杂页面中验证。

## 6. 阶段 4：发现与智能检索

- 首页内容模块、分类、标签、搜索、筛选、排序和建议。
- 可解释综合评分、索引任务、无结果体验和 URL 状态。
- 搜索性能指标和质量分析事件。

## 7. 阶段 5：互动与通知

- 点赞、收藏夹、评论、关注、举报和站内通知。
- 去重、计数策略、评论治理状态和通知偏好。

## 8. 阶段 6：存证与核验

- 规范化、SHA-256、Merkle Tree、本地模拟器和 Gateway API。
- Java 任务状态机、公开证明页、核验入口和证书。
- 真实长安链适配器接入、异常分类和环境标识。

## 9. 阶段 7：管理治理

- 用户、内容、评论、举报、分类标签、证明任务和审计。
- 高风险动作确认、原因、权限和恢复语义。
- 管理总览聚焦待处理项与系统健康。

## 10. 阶段 8：系统收敛

- 性能预算、安全加固、可访问性、国际化完整性。
- 备份恢复、部署说明、演示数据和答辩流程。
- 需求追踪、架构图、接口文档和最终限制说明。

## 11. 纵向切片完成顺序

每一项功能按以下顺序完成：

1. 需求和验收条件。
2. 权限与状态。
3. OpenAPI 和错误码。
4. 数据模型与约束。
5. Mock 正常和失败场景。
6. 前端页面和交互。
7. Java Controller、Service、Repository、Entity。
8. 契约联调。
9. 日志、指标和审计。
10. 文档与证据更新。
