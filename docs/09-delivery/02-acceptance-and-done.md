# 验收标准与完成定义

- 状态：Accepted

## 1. 项目级验收

- 公开用户、注册用户、创作者和管理员均有完整关键旅程。
- 资源从草稿到发布、检索、互动、存证、核验和治理形成闭环。
- Mock 与真实后端模式不修改业务页面即可切换。
- 中文和英文覆盖所有核心页面与错误状态。
- 真实链与模拟器来源明确，证明语义一致。
- Java 代码符合模块化 MVC 边界，没有跨模块 Repository 访问。
- 安全、性能、可访问性和可观测性达到文档基线。

## 2. 功能完成定义

一个功能只有在以下条件全部满足时才算完成：

1. 需求编号与验收条件已批准。
2. 页面正常、加载、空、错误和权限状态已设计。
3. 中文、英文和可访问性内容已完成。
4. OpenAPI、错误代码、权限、幂等和并发规则已定义。
5. Mock 正常和关键失败场景可复现。
6. Java MVC 各层职责清楚，事务边界正确。
7. 数据约束、索引和保留规则已落实。
8. 日志、指标和必要审计已加入。
9. 验证证据通过，已知限制已记录。
10. 权威文档与实现一致。

## 3. 页面完成定义

- 响应式布局覆盖 320px、768px、1280px 和宽屏。
- 键盘可操作，焦点清晰，对比度合格。
- 中文和英文长文本不溢出。
- 加载不造成明显布局跳动。
- 空状态给出合理下一步。
- 错误状态包含请求标识和恢复操作。
- 破坏性操作有明确影响说明。
- 没有硬编码用户可见文案。
- 没有直接网络请求和重复基础组件。

## 4. API 完成定义

- 请求和响应符合 OpenAPI。
- 权限在后端执行。
- 校验错误和业务错误可区分。
- 列表有稳定排序和有界分页。
- 写操作的幂等与并发行为明确。
- Entity 未直接暴露。
- 敏感字段不进入响应和日志。
- 指标能够观察成功、失败和延迟。

## 5. 存证完成定义

- 规范化规则和摘要测试向量固定。
- 模拟器与真实适配器使用相同内部模型。
- 结果未知不会直接创建重复交易。
- 已确认证明与证书状态分离。
- 证书显示来源、版本、摘要和核验入口。
- 核验区分匹配、不匹配、未找到和不可用。
- 正式环境无法启用模拟回退。

## 6. 答辩演示验收

- 演示环境一键识别当前 API 模式和证明来源。
- 演示数据固定、可复位、无个人敏感信息。
- 主流程不依赖不稳定公网服务。
- 准备真实链可用和不可用两种说明路径。
- 能解释技术路线、MVC 分层、双模式、存证幂等和检索评分。
- 系统限制与未来方向表述诚实，不把模拟器或启发式检索夸大。
