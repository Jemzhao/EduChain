# 角色、权限与用例

- 状态：Accepted

## 1. 角色模型

| 角色          | 说明                             | 获取方式           |
| ------------- | -------------------------------- | ------------------ |
| Visitor       | 未登录访问者                     | 默认               |
| User          | 正常注册用户，可阅读、互动和创作 | 注册并通过基础校验 |
| Moderator     | 内容治理人员                     | 管理员显式授予     |
| Administrator | 平台管理人员                     | 受控授予与审计     |

角色决定能力上限，对象关系和资源状态进一步决定是否允许具体操作。前端仅用于呈现，最终授权由 Java 后端完成。

## 3. 对象级授权规则

- 用户只能修改自己的草稿和资料。
- 已发布内容的修改生成新版本，不覆盖已存证版本。
- Moderator 通过治理接口处理内容，不直接获得作者编辑能力。
- Administrator 不能读取密码哈希、刷新令牌、密钥或不必要的敏感字段。
- 私有附件通过短时授权地址访问，不能依赖不可猜测 URL 作为权限控制。
- 被停用用户不能创建新会话或产生写操作，但公开内容的处理由治理规则决定。

## 4. 关键用例前置与结果

### UC-01 发布资源

- 前置：用户已登录、状态正常、资料满足最低要求。
- 主结果：生成公开资源版本，触发索引和存证任务。
- 失败：字段错误、附件未完成、内容风险、并发版本冲突或系统暂不可用。
- 幂等：同一发布命令重复到达，只能产生一个目标版本。

### UC-02 核验资源

- 前置：访问者拥有证明标识、交易标识、资源版本链接或待验证文件。
- 主结果：返回匹配结果和可公开的证明信息。
- 失败：记录不存在、文件摘要不匹配、证明后端不可用或数据格式无效。
- 隐私：上传用于核验的文件遵循临时保存和自动清理规则。

### UC-03 下架资源

- 前置：作者主动下架本人资源，或治理角色基于权限处理。
- 主结果：资源不再出现在普通列表和搜索结果中，直接访问显示状态说明。
- 保留：资源版本、存证记录和审计轨迹按规则保留。

### UC-04 管理员调整用户状态

- 前置：管理员通过强认证，目标用户存在，操作不违反角色保护规则。
- 主结果：状态生效，相关会话按策略撤销，记录原因和操作者。
- 保护：管理员不得停用自己或最后一个可用管理员。

## 5. 高风险动作

以下动作需要二次确认、原因和审计：

- 停用用户。
- 下架或恢复资源。
- 隐藏或恢复评论。
- 合并或停用分类标签。
- 手工重试或终止存证任务。
- 撤销全部会话。
