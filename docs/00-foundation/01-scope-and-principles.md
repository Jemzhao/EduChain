# 范围、非目标与设计原则

- 状态：Accepted

## 1. 产品范围

### 1.1 账户与身份

- 邮箱或用户名注册、登录、退出、令牌刷新。
- 个人资料、头像、教育背景、个人简介和公开主页。
- 密码修改、密码重置、会话管理和异常登录提示。
- 用户状态：正常、受限、停用。

### 1.2 知识资源

- 草稿创建、编辑、自动保存、预览、发布、下架和删除。
- 标题、摘要、正文、封面、附件、分类、标签、可见性和版权声明。
- Markdown 或结构化富文本作为正文输入，渲染前经过安全清洗。
- 资源版本快照与公开版本标识。

### 1.3 发现与检索

- 关键词检索、分类筛选、标签筛选、作者筛选和时间范围。
- 相关度、最新、热度和质量排序。
- 搜索建议、近期搜索、无结果引导和结果高亮。
- 可解释的综合评分：文本相关度、资源质量、时效性和互动信号。

### 1.4 社区互动

- 点赞、取消点赞、收藏、收藏夹管理。
- 一级评论与受控回复，不建设无限层级讨论树。
- 关注、取消关注、关注者与正在关注列表。
- 站内通知、已读状态、批量已读和通知偏好。

### 1.5 区块链存证

- 对发布版本计算 SHA-256 摘要。
- 对摘要、作者标识、资源标识、版本标识和时间信息进行存证。
- 存证任务状态查询、失败原因、重试和人工处理。
- 公开核验页、交易信息、证书下载和二维码核验入口。
- 长安链真实适配器与本地模拟器，二者结果必须显式标注来源。

### 1.6 管理治理

- 用户查询、状态调整和操作审计。
- 资源审核、下架、恢复和风险标记。
- 分类与标签治理。
- 评论治理、举报处理和基础运营统计。
- 系统健康、失败任务和安全事件概览。

## 2. 首个正式版本不包含

- 在线课程售卖、支付、结算、广告和收益分成。
- 直播、实时音视频课堂和即时聊天。
- NFT、代币、链上资产交易或公开链钱包体系。
- 版权交易、授权合同自动执行和版税分配。
- 原生移动端应用。
- 多租户学校 SaaS、组织级计费和复杂组织架构。
- 通用工作流引擎、微服务拆分和服务网格。
- 依赖外部大模型才能工作的核心搜索流程。

## 3. 设计原则

### 3.1 清晰优先

用户先理解“资源、作者、原创证明、核验结果”，再接触“交易哈希、区块高度、共识”等术语。界面不以技术名词制造复杂感。

### 3.2 契约优先

页面、Mock、Java 后端和存证网关围绕同一套接口契约工作。任何一方不得自行发明字段、状态或错误语义。

### 3.3 单一事实来源

- MySQL：业务状态和关系事实。
- 对象存储：文件内容。
- 长安链：存证事实。
- Intlayer：用户可见内容。
- OpenAPI：HTTP 契约。
- 设计令牌：颜色、字号、间距、圆角、阴影和动效参数。

### 3.4 默认安全

所有输入都不可信；所有公开输出都经过清洗；所有权限都在服务端复核；所有高风险操作都留下审计记录。

### 3.5 失败是正常状态

上传、发布、存证、证书生成、通知和索引更新都有明确的处理中、成功、失败、可重试和终止状态，界面不假设外部依赖永远可用。

### 3.6 克制的高级感

视觉质量来自排版、间距、层级、响应速度、细节和一致性，而不是高饱和颜色、重阴影、玻璃效果或持续动画。

### 3.7 可解释的智能

搜索排序和推荐必须能说明主要信号。首版不使用无法稳定复现的黑盒结果作为唯一排序依据。

## 4. 冲突决策顺序

当目标冲突时，按以下顺序决策：

1. 数据正确性与安全。
2. 用户任务是否能完成。
3. 契约和状态是否一致。
4. 可维护性与可解释性。
5. 性能和资源成本。
6. 视觉表现与附加功能。
