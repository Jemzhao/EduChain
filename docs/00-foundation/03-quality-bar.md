# 质量基线

- 状态：Accepted

## 1. 质量定义

高质量不是堆叠框架或增加抽象层，而是使系统在正确性、清晰度、安全性、可访问性、性能、可观测性和文档一致性上都有可验证标准。

## 2. 架构要求

- 每个业务能力有唯一归属模块。
- 模块依赖方向明确，不允许循环依赖。
- Controller 不包含业务规则，Repository 不返回接口响应对象。
- Entity 不直接序列化到外部接口。
- 前端页面不直接拼接 API 地址，不直接读取不受控响应。
- Mock 与真实后端共享路径、方法、请求模型、响应模型和错误模型。
- 存证网关对 Java 后端提供稳定接口，长安链 SDK 细节不得泄漏到业务模块。

## 3. 代码阶段的静态质量门禁

以下规则在进入实现阶段后生效：

- TypeScript 使用严格模式，禁止无理由的 `any`。
- Java 编译警告按约定处理，核心模块使用架构规则检查依赖边界。
- Python 使用静态类型检查与统一格式化。
- 重复代码、未使用导出、循环依赖和硬编码用户文案作为阻断问题。
- 数据库结构变更必须有可重复执行的版本脚本和回退说明。
- OpenAPI 变更必须经过兼容性检查。

## 4. 安全基线

- 密码使用自适应密码哈希算法，绝不记录明文或可逆密文。
- 访问令牌短时有效，刷新令牌可撤销、可轮换。
- 管理权限默认拒绝，后端不信任前端隐藏按钮。
- 上传文件执行大小、扩展名、MIME、文件签名和存储路径检查。
- 富文本输出执行白名单清洗，链接和嵌入内容受控。
- 所有写接口具备 CSRF、重放、越权、批量枚举和滥用风险评估。
- 公开错误不泄漏堆栈、SQL、密钥、内部路径或第三方响应原文。

## 5. 可用性与可访问性

- 键盘能够完成所有核心流程。
- 焦点状态清楚，焦点顺序符合视觉顺序。
- 文本和重要图标满足 WCAG 2.2 AA 对比度。
- 表单错误同时提供文字、位置和可读关联，不只依赖颜色。
- 支持系统减少动态效果偏好。
- 主要页面在 320px 至宽屏范围内没有横向内容丢失。

## 6. 性能预算

| 指标     | 公开页面目标                                          | 登录后应用页目标            |
| -------- | ----------------------------------------------------- | --------------------------- |
| LCP      | 第 75 百分位不高于 2.5 秒                             | 第 75 百分位不高于 2.5 秒   |
| INP      | 第 75 百分位不高于 200 毫秒                           | 第 75 百分位不高于 200 毫秒 |
| CLS      | 不高于 0.1                                            | 不高于 0.1                  |
| API 读取 | 服务端第 95 百分位不高于 300 毫秒，不含外部存证       | 同左                        |
| API 写入 | 服务端第 95 百分位不高于 500 毫秒，不含文件与外部存证 | 同左                        |
| 搜索     | 第 95 百分位不高于 800 毫秒                           | 同左                        |

性能数字是设计预算，最终验收需在明确数据规模和环境下执行。

## 7. 可观测性

- 每个请求有统一追踪标识。
- 日志使用结构化字段并进行敏感信息脱敏。
- 核心指标覆盖请求量、错误率、延迟、队列积压、缓存命中、存证任务和索引状态。
- 关键业务事件能够关联用户、资源版本、存证任务和交易标识。
- 健康检查区分存活、就绪和外部依赖状态。

## 8. 文档质量

- 任何核心状态、枚举、错误码、权限或环境变量只定义一次。
- 图示、目录树和文字说明必须一致。
- 每个需求至少有一个验收条件。
- 每个接口至少记录调用方、权限、幂等性、错误和分页规则。
- 每个风险至少记录触发信号、影响和处理策略。
