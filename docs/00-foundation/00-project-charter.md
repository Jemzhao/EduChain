# 项目章程

- 状态：Accepted
- 项目名称：EduChain
- 中文名称：基于区块链存证的教育知识共享与智能检索系统
- 文档责任：产品负责人、架构负责人

## 1. 项目使命

EduChain 为教师、学生和教育内容创作者提供一个可信、清晰、可检索的知识共享平台。系统将资源发布、内容发现、互动协作、原创存证、真实性核验和平台治理放在同一条可理解的用户路径中，使教育资源既容易传播，也能保留可验证的原创凭据。

## 2. 要解决的问题

1. 教育资源分散，分类、标签和检索体验不一致，优质内容难以被发现。
2. 原创资源发布后容易被复制或改写，作者缺少时间明确、内容固定、可独立核验的证明材料。
3. 常见内容平台把版权信息仅保存在中心化数据库中，证明力和可追溯性不足。
4. 内容分享、互动、收藏、关注、通知和管理能力往往彼此割裂。
5. 复杂技术容易被直接暴露给普通用户，导致“区块链功能存在但不可用、不可理解”。

## 3. 成功定义

系统成功不以页面数量或接口数量衡量，而以关键闭环是否完整衡量：

- 用户能够安全注册、登录并管理个人资料。
- 创作者能够创建草稿、上传附件、预览、发布资源并查看处理状态。
- 读者能够通过关键词、分类、标签和排序快速找到资源。
- 用户能够点赞、收藏、评论、关注，并收到明确、可管理的通知。
- 符合条件的资源能够生成哈希、提交存证、查询结果、生成证书并公开核验。
- 管理员能够治理用户、内容、分类、标签与风险事件。
- Mock 模式与真实后端模式在页面、状态和错误语义上保持一致。
- 中文与英文界面使用同一套内容治理机制，组件内没有散落文案。

## 4. 项目形态

- Web 前端：面向普通用户和管理员的统一 Next.js 应用。
- Java 后端：模块化 MVC 单体，承载账户、内容、互动、检索、通知、管理等核心业务。
- 存证网关：独立 FastAPI 服务，封装长安链 SDK、哈希、证书与本地模拟器。
- 数据基础：MySQL 作为业务事实来源，Redis 承载缓存、限流、短期状态与检索辅助数据。
- 文件能力：通过统一对象存储抽象保存资源文件、头像和证书；本地开发使用文件系统适配器。

## 5. 约束

- 前端核心技术路线与论文保持一致：Next.js、React、TypeScript、Tailwind CSS。
- 后端核心技术路线与论文保持一致：Java、Spring Boot、Spring MVC、Spring Security、MySQL、Redis。
- 存证路线与论文保持一致：Python、FastAPI、长安链、SHA-256、Merkle Tree、本地模拟器。
- Java 后端不得使用难以解释的过度分层；必须能用标准 MVC 术语说明每一层职责。
- 系统必须支持无长安链环境的完整本地演示，但不得把模拟结果伪装成真实链上结果。
- 默认界面必须满足 WCAG 2.2 AA 的核心要求。
- 所有关键状态必须可观测、可追踪、可重试或可人工处理。

## 6. 利益相关者

| 角色         | 关注点                                 | 决策参与     |
| ------------ | -------------------------------------- | ------------ |
| 毕业设计作者 | 完整性、可解释性、论文一致性、答辩演示 | 最终决定     |

| 系统维护者   | 清晰结构、故障定位、配置与部署         | 技术评审     |

## 7. 阶段出口

开发前阶段只有在以下条件全部满足后才结束：

1. 文档导航完整，不存在职责重叠的权威文档。
2. 关键技术版本有官方依据，并记录版本锁定策略。
3. 产品需求可追溯到页面、接口、数据和验收条件。
4. Mock/真实后端双模式有明确开关、契约和防漂移机制。
5. Java MVC 目录与模块依赖规则已冻结。
6. 存证状态机、幂等键、失败处理和核验口径已冻结。
7. 风险清单明确负责人、信号和应对动作。
