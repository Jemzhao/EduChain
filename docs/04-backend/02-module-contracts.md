# Java 业务模块边界

- 状态：Accepted

## 1. `auth`

责任：注册凭据、登录、令牌刷新、退出、密码重置、会话撤销和认证事件。

拥有：凭据、刷新会话、重置凭据、认证尝试。

不拥有：公开个人资料、角色治理、业务通知展示。

公开用例：注册、认证、刷新、退出、重置密码、列出与撤销会话。

## 2. `user`

责任：用户状态、公开资料、头像引用、角色和账户偏好。

拥有：用户、资料、角色关联、状态历史。

不拥有：密码、资源内容、关注关系。

公开用例：读取本人、更新资料、读取公开主页基础信息、调整用户状态和角色。

## 3. `knowledge`

责任：资源草稿、公开资源、不可变版本、可见性、发布和下架。

拥有：资源、草稿内容、发布版本、版本附件引用、版权声明。

不拥有：附件对象本身、分类定义、点赞关系、证明交易。

公开用例：创建草稿、保存、预览、发布、读取、列出本人资源、下架、恢复。

## 4. `taxonomy`

责任：分类、标签、别名、排序、启用状态和引用校验。

拥有：分类、标签、别名和治理状态。

不拥有：资源关联的业务生命周期。

公开用例：读取分类标签、管理分类标签、校验选择、提供检索筛选元数据。

## 5. `search`

责任：查询解析、筛选、综合评分、建议词、搜索行为记录和索引任务协调。

拥有：搜索事件、建议词、派生索引状态。

不拥有：资源事实、分类事实和互动事实。

公开用例：搜索、建议、热门查询、资源索引更新和重建。

### 5.1 综合评分

首版评分由以下可解释信号组成：

- 标题、摘要、正文、标签和作者字段相关度。
- 分类与筛选匹配。
- 内容完整度与治理质量分。
- 发布时间衰减。
- 去异常后的点赞、收藏、评论和阅读信号。

具体权重配置化、版本化并记录在搜索响应调试信息中；普通用户只看到排序说明，不暴露可被利用的完整公式。

## 6. `interaction`

责任：点赞、收藏、收藏夹、评论、回复和举报。

拥有：互动关系、评论内容、评论状态、举报记录。

不拥有：关注关系、通知记录和资源计数事实。

公开用例：切换点赞、管理收藏、发表评论、删除本人评论、治理评论、提交举报。

## 7. `social`

责任：关注关系、关注列表和关系状态。

拥有：关注关系。

规则：不能关注自己；任一用户状态受限时阻止新关系；同一关系唯一。

## 8. `notification`

责任：站内通知、已读状态、偏好和发送任务。

拥有：通知记录、用户通知偏好、外部通道发送状态。

不拥有：产生通知的业务事实。

公开用例：列出通知、标记已读、批量已读、更新偏好、接收业务通知意图。

## 9. `file`

责任：上传会话、对象元数据、安全状态、摘要、访问授权和清理。

拥有：文件对象记录、上传会话、扫描结果、存储键。

不拥有：资源与附件的业务顺序和展示说明。

公开用例：创建上传、完成上传、查询状态、绑定前校验、生成受控访问地址、清理过期对象。

## 10. `evidence`

责任：证明请求、任务状态、证明记录、核验协调和证书引用。

拥有：证明任务、证明记录、核验事件、证书元数据。

不拥有：长安链密钥、SDK 配置和证书二进制生成细节。

公开用例：为资源版本创建任务、查询状态、处理任务、公开证明、核验、受控重试和终止。

## 11. `admin`

责任：组合治理视图和管理用例入口。

不拥有核心业务表。所有状态变更委托对应模块公开管理 Service。

内部按总览、用户、内容、分类、存证和可观测性拆分用例服务；Controller 不共享万能管理门面，返回模型由统一管理 Mapper 组装。

## 12. `audit`

责任：写入和查询只追加审计事件。

拥有：审计事件。

规则：业务模块可以写入；普通模块不能修改或删除；查询按权限脱敏。

## 13. `job`

责任：可靠任务的通用领取、租约、重试计划和执行指标。

不拥有具体业务任务载荷的解释权。业务模块实现处理器和状态映射。

## 14. 跨模块调用示例

- `knowledge` 发布前调用 `file` 校验对象可用，调用 `taxonomy` 校验分类标签。
- `knowledge` 发布事务创建完成后，由可靠任务触发 `search` 和 `evidence`。
- `interaction` 成功创建评论后向 `notification` 提交通知意图。
- `admin` 下架资源时调用 `knowledge` 管理 Service，并调用 `audit` 记录动作。
- `evidence` 通过 `KnowledgeEvidencePort` 读取发布版本快照并调用 Gateway 客户端，不依赖 `knowledge` Service 或 Repository。
- `knowledge` 通过 `EvidenceStatusPort` 批量读取存证处理状态，不依赖 `evidence` Service 实现。
- `user` 通过统计与会话撤销端口获得知识数量、关注数量和认证会话撤销能力，不反向依赖对应模块实现。
- 跨模块端口和稳定快照只放在 `platform/port` 与 `platform/contract`，不得把业务 Repository 或 Entity 放入平台层。
